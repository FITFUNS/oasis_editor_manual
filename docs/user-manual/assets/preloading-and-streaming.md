---
title: 사전 로드 및 스트리밍 (Preloading and Streaming)
---

웹에서는 페이지가 열린 뒤 **얼마나 빨리 게임을 시작할 수 있는지**가 중요합니다. 로딩 바를 오래 띄워 두면 게임이 시작되기도 전에 방문자가 떠나 버립니다. OasisW의 에셋 시스템에는 로딩 과정을 다듬고 애플리케이션을 최대한 빨리 실행시키기 위한 기능이 여러 가지 들어 있습니다.

## 사전 로드 (Preload)

프로젝트의 모든 에셋에는 `preload`라는 속성이 있습니다. **기본값은 켜짐(true)**입니다. 사전 로드로 표시된 에셋은 애플리케이션의 초기화 단계가 시작되기 *전에* 모두 내려받아 준비됩니다.

에디터에서는 에셋을 선택했을 때 인스팩터에 `Preload` 체크박스로 나타납니다. 옆의 **?** 를 누르면 다음 설명이 나옵니다.

> If true the asset will be loaded during the preload phase of application set up.

게임이 시작되자마자 필요한 에셋은 사전 로드로 두십시오. 그래야 시작한 뒤에 물체나 텍스처가 뒤늦게 **'툭' 하고 나타나는 현상**을 막을 수 있습니다.

:::warning 모두 켜 두면 될까요

사전 로드를 켠 에셋이 많아질수록 **첫 화면이 뜨기까지 걸리는 시간이 길어집니다**. 시작하자마자 보이는 것만 켜 두고, 두 번째 스테이지에서야 등장하는 에셋은 꺼 두는 편이 좋습니다.

:::

## 스트리밍

씬의 엔티티가 어떤 에셋을 참조하고 있으면, **그 엔티티가 활성화되는 순간** 로딩 요청이 시작됩니다. 엔티티가 처음부터 활성 상태라면 애플리케이션이 시작되자마자 요청이 나갑니다.

모든 컴포넌트는 이렇게 나중에 도착하는 에셋을 문제없이 처리하며, 에셋이 도착하면 그때부터 정상 동작합니다. 다만 이런 방식에서는 앞서 말한 **'팝업'**을 보게 되는 경우가 많습니다. 예를 들어 모델은 재질이나 텍스처가 아직 없어도 로드되는 즉시 화면에 나타납니다.

## 에셋은 언제 로드되나요

특정 에셋이 언제 로드될지는 다음 순서로 판단하면 됩니다.

1. `preload = true`이면 **애플리케이션이 시작되기 전에** 로드됩니다. 그렇지 않다면 아래로 넘어갑니다.
2. 씬 계층 구조 안에 있고 **활성화된 엔티티의 활성화된 컴포넌트**가 그 에셋을 참조하면 로드됩니다. 엔티티나 컴포넌트가 활성화되는 시점, 또는 에셋이 컴포넌트에 할당되는 시점에 로딩이 시작됩니다. 여기서 '컴포넌트가 활성화되어 있다'는 것은 *컴포넌트 자신도 켜져 있고, 그 위쪽 계층의 엔티티가 모두 켜져 있다*는 뜻입니다.
3. 이미 로드된 **다른 에셋이 참조하는** 에셋도 따라서 로드됩니다. 모델이 로드되면 그 모델이 쓰는 재질이 로드되고, 재질이 쓰는 텍스처가 다시 로드되는 식입니다.

:::note 정리하면

사전 로드로 표시했거나, 화면에 켜져 있는 무언가가 쓰고 있거나, 이미 로드된 에셋이 물고 있으면 로드됩니다. 셋 다 아니면 로드되지 않습니다.

:::

## 에셋 태그 {#asset-tags}

에셋이 하나씩 도착하면서 화면에 '팝업'되는 것이 보기 싫을 때가 많습니다. 이럴 때는 **필요한 에셋을 한 묶음으로 미리 다 받아 놓고, 다 받은 뒤에 한꺼번에 보여 주는** 방식이 좋습니다. 이를 위해 에셋에 **태그**를 붙여 그룹을 만들 수 있습니다.

태그는 인스팩터의 `Tags` 칸에서 붙입니다. 예를 들어 1스테이지에서 쓰는 에셋에 모두 `level-1`이라는 태그를 붙여 두는 식입니다. 태그를 붙인 에셋들은 `preload`를 꺼 두어야 이 방식이 의미가 있습니다.

다음은 특정 태그가 붙은 에셋을 모두 로드하고, 전부 끝났을 때를 감지하는 JavaScript 예시입니다.

```javascript
const assets = this.app.assets.findByTag("level-1");
let count = 0;

for (let i = 0; i < assets.length; i++) {
    assets[i].once("load", function () {
        count++;
        if (count === assets.length) {
            // 에셋 로딩 완료
        }
    });
    this.app.assets.load(assets[i]);
}
```

이 코드를 [스크립트](/user-manual/scripting/fundamentals/getting-started)에 넣고 로딩 화면과 함께 쓰면, 에셋이 다 준비된 다음에 스테이지를 보여 줄 수 있습니다.

## 스크립트 로딩 순서

스크립트 에셋은 다른 에셋과 달리 **읽어 들이는 순서**가 중요할 때가 있습니다. 어떤 스크립트가 다른 스크립트에서 정의한 것을 쓰는 경우입니다.

스크립트 에셋을 선택하면 인스팩터에 `Loading Order` 항목과 **MANAGE** 버튼이 나타납니다. 이 버튼을 누르면 **SETTINGS › SCRIPTS LOADING ORDER**로 이동하며, 여기에서 순서를 조정할 수 있습니다.

같은 자리에 `Loading Type` 항목도 있습니다. 기본값은 `Asset`이며, 스크립트를 일반 에셋처럼 로드한다는 뜻입니다.

## 로딩이 느릴 때 점검할 것

- **사전 로드를 켠 에셋이 너무 많지 않은지** 확인하십시오. 첫 화면에 필요 없는 것은 끕니다.
- **텍스처 해상도**를 확인하십시오. 화면에서 작게 보이는 물체에 4K 텍스처를 쓸 필요는 없습니다.
- **오디오는 `.mp3`나 `.ogg`**로 올리십시오. WAV는 용량이 몇 배 큽니다.
- **쓰지 않는 에셋**은 인스팩터의 `Exclude`를 켜서 게시 결과물에서 빼거나 삭제하십시오.
- **3D 모델은 GLB**로 통일하십시오. 자세한 내용은 [3D 모델 가져오기](/user-manual/assets/models)를 참고하십시오.
