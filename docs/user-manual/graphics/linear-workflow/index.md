---
title: 선형 워크플로우 (Linear Workflow)
---

빛과 색을 실제처럼 자연스럽게 표현하려면 선형 워크플로우가 꼭 필요합니다. 핵심은 간단합니다. 셰이딩부터 후처리까지 모든 색 계산을 "선형 색 공간"에서 하는 것입니다. 이렇게 하면 감마 압축된 텍스처나 잘못된 색 섞임 때문에 생기는 오류를 막을 수 있습니다. 계산은 선형 공간에서 하고 감마 보정은 맨 마지막 출력 단계에서만 적용하면, 조명·텍스처·효과가 서로 어긋나지 않고 잘 맞아 더 사실적이고 예측 가능한 결과를 얻습니다.

## 셰이더 입력 및 출력 처리

선형 워크플로우가 제대로 동작하려면 셰이더 안의 모든 색 계산이 물리적으로 맞는 방식으로 이뤄져야 합니다. 그러려면 셰이더로 들어가는 값(입력)과 셰이더가 내보내는 값(출력)을 둘 다 신경 써서 다뤄야 합니다.

### **셰이더 입력: 선형 데이터 보장**

조명이 이상하게 계산되지 않으려면, 셰이더로 들어가는 모든 값이 선형 공간에 있어야 합니다. 이는 텍스처와 유니폼 색상 값 모두에 해당합니다:

- 색을 담고 있는 **텍스처**(예: 알베도 맵)는 **sRGB**로 표시해야 합니다. 이렇게 하면 텍스처를 읽을 때 GPU가 sRGB로 저장된 값을 자동으로 선형 공간으로 바꿔 주므로 색 계산이 올바르게 됩니다.
- **색상 유니폼**은 `StandardMaterial`, 파티클 렌더링을 비롯한 엔진 내장 렌더링 시스템에서는 감마 공간에서 선형 공간으로 자동 변환됩니다. 다만 `Material.setParameter`나 `MeshInstance.setParameter`로 유니폼을 직접 넣을 때는, 값을 선형 공간으로 넘겨 주는 일이 여러분(호출자)의 몫입니다. 특히 모든 매개변수를 `setParameter`로 직접 지정해야 하는 `ShaderMaterial`에서 이 점이 중요합니다. 이를 돕기 위해 `Color` 클래스는 감마 공간 색을 선형 공간으로 바꿔 주는 `Color.linear()` 함수를 제공합니다.

이렇게 모든 입력이 선형 공간에 있으면 셰이더는 물리적으로 정확한 조명 계산 결과를 냅니다.

### **셰이더 출력: 감마 보정 관리**

최종 색을 내보낼 때 감마 보정을 어떻게 처리할지는 렌더링이 LDR(저역동범위)인지 HDR(고역동범위)인지에 따라 달라집니다:

- **LDR 렌더링**: 색을 렌더 타겟에 쓰기 직전에 셰이더에서 바로 감마 보정합니다. 그래야 일반 모니터에서 제대로 보입니다.
- **HDR 렌더링**: 색을 렌더 타겟에 쓸 때는 선형 공간 그대로 둡니다. 이때는 정밀도를 지키고 밴딩(색 경계가 계단처럼 보이는 현상)을 막기 위해 보통 **부동소수점 형식**(예: `RGBA16F` 또는 `RGBA32F`)이 필요합니다. 감마 보정은 나중에, 보통 최종 톤 매핑이나 후처리 단계에서 적용합니다. 그래야 블룸이나 컬러 그레이딩 같은 효과가 정밀한 선형 HDR 색을 그대로 활용할 수 있습니다.

이런 순서를 지키면 조명·블렌딩·후처리가 서로 일관되게 맞물려, 더 사실적이고 예측 가능한 렌더링 결과를 얻습니다.
